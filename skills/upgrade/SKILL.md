---
name: upgrade
description: Bring a repository up to the installed lifecycle kit — guides pinned to the kit's release, templates installed or ported into the repository's own files; a task's first step when the kit moved, or run alone after a pause
---

The clarify skill runs these steps as a tracked task's first step when `lifecycle doctor` names `upgrade`, and the review skill when a minor release blocks a work round. Run them alone after a pause, or before an untracked task's first edit. `lifecycle` is the kit's command: on PATH with the kit's Claude plugin, otherwise `bin/lifecycle` in a checkout of the kit.

1. `lifecycle doctor`. It lists what the kit changed since this repository's release, the `Repositories:` lines first; on a first move onto the kit, its `adopt` finding lists every `Repositories:` line up to the installed release.
   - A line that changes something outside the tree (a branch on GitHub, a repository setting) comes before anything is written. Inside a task, stop the upgrade there and tell the maintainer it runs alone first: the task waits, its uncommitted files staying in the tree and out of the upgrade's commit, and goes on once the line and what it asks to follow are done. The upgrade's own work round diffs only the paths the upgrade wrote (`git diff -- <paths>`), and a release the line asks for leaves the waiting task's open issue in its milestone to the maintainer. Run alone, make the line only on the maintainer's go-ahead and in the order it gives. A declined one stops the upgrade with nothing written; a failed one stops it and names what the line already changed outside the tree.
   - A line that changes `.lifecycle.toml` is made next, before step 2, since the upgrade reads those settings: `[templates]` decides which templates it replaces and names.

   Step 4 makes the rest.
2. `lifecycle upgrade`. It copies the kit's method into the guides folder and pins `.lifecycle.lock` to the installed release. It replaces each file a template ports into that still holds the template's old text word for word (usually the issue and PR templates) with the new text, and names the templates left to port, each with the file it ports into: `[templates]` in `.lifecycle.toml`, or a project's defaults where it names none (`lifecycle config` prints them). A guide edit not yet in the kit is carried onto the new release by a three-way merge, and a conflict stops the upgrade with nothing written: resolve it with the maintainer. A carried edit still goes to the kit at its task's *Complete*.
3. **The templates left to port.** For each one, read what the method changed: `git diff -- <the template>`, or the whole file for a template the upgrade added (`??` in `git status --short`). Port what applies into the file the upgrade named for it, in the repository's words, keeping what it decided for itself. Port nothing that does not apply, and say what was left and why.
4. **What the release requires.** `lifecycle upgraded` lists the kit's `Repositories:` lines between the two releases, or every one up to the release on a first move onto the kit: changes every repository makes beyond its guides and templates (a setting, a hook, a CI step, a settings key). Make each one not made at step 1 in this repository, in its words, and name the files it touched; one that does not apply here, say so and why. Each line names the file it changes, so a later session finds those files from the line itself.
5. `lifecycle doctor` reads clean, apart from the carried edits it names and a note that a newer kit is out, which stops nothing: name it in the *Upgrade* line.
6. **Hand back.**
   - Inside a task, the briefs' *Upgrade* line carries it (`lifecycle upgraded` reads it from the tree in any later session), and the complete skill's commit rule lands it.
   - Run alone, render the hand-back brief by the handback skill. With nothing ported and no required change made, the round is skipped. Otherwise run the review skill untracked: the base reviewer reads each port against its template's diff, and each required change against its `Repositories:` line. *Complete* commits it as `docs(guides): upgrade to kit <release>`.
